## 1. 目标

- 将当前 CHM 解压目录中的 HTML 文档、CSS、图片/资源、目录结构完整迁移到 TiddlyWiki。
- 保持原有书籍/章节/条目的组织方式，便于搜索、标签浏览和双链。
- 修复 CHM 内部相对链接、锚点、索引，使其在 TiddlyWiki 中可用。
- 最终产物建议为：
  - TiddlyWiki5 的 `tiddlers` 文件夹（`.tid` / `.json`），可被 Node.js 版 TiddlyWiki 加载；或
  - 单文件 TiddlyWiki（`output.html`），便于直接打开和分发。

## 2. 现状盘点

- 根目录包含 CHM 编译残留文件：
  - `#IDXHDR`、`#ITBITS`、`#IVB`、`#STRINGS`、`#SYSTEM`、`#TOPICS`、`#URLSTR`、`#URLTBL`、`#WINDOWS`
  - `$FIftiMain`、`$OBJINST`
  - `$WWAssociativeLinks\`、`$WWKeywordLinks\`
- 导航/索引文件：

  - `Index.hhk`（CHM 索引）
- 主内容为大量 `.htm` 文件，按中文分类目录组织，例如：
  - `0 核心三宝书\`、`1 核心补充书籍\`、`2 万物万法万律\` …
  - 每个分类下有若干书籍子目录
- 存在公共样式：`cascading_stylesheet.css`
- 存在前言、使用说明、版本历史等页面。

## 3. 迁移策略

采用“目录结构 -> Tiddler 标签树 + 标题命名 + 相对链接改写 + 目录 Tiddler”的方式：

1. **保留目录层级为标签体系**
   - 一级目录（`0 核心三宝书` 等）作为大类标签
   - 二级目录（`PHB玩家手册` 等）作为书籍/模块标签
   - 文件本身转换为一个 Tiddler

2. **每个 HTML 页面转换为一个 Tiddler**
   - 优先使用 HTML `<title>` 或 `<h1>` 生成 Tiddler 标题
   - 标题冲突时追加目录前缀或文件名消歧
   - Tiddler 正文保留为 HTML 片段（TiddlyWiki 支持 HTML）
   - 正文中的 HTML 标签名统一转为小写，例如 `<H1>` -> `<h1>`

3. **目录树/索引转为导航 Tiddler**
   - 解析 `Contents.hhc`，生成“总目录”Tiddler
   - 通过右侧边栏“目录”标签页展示
   - 不再为每本书单独生成“书名 - 目录”Tiddler
   - 解析 `Index.hhk`，生成“索引”Tiddler（可选）

4. **资源统一处理**
   - 图片作为 TiddlyWiki 二进制 Tiddler 放入 `wiki/tiddlers/` 对应子目录
   - 每个图片文件旁生成 `.meta` 文件，将标题设为相对路径
   - 页面中使用 `[img[相对路径]]` 引用图片

5. **链接改写**
   - 解析 `<a href="xxx.htm#anchor">`：
     - `xxx.htm` -> 对应 Tiddler 标题 `[[标题]]`
     - `#anchor` -> 保留为 Tiddler 内锚点（需给标题/元素加 id）
   - 解析 `<img src="...">`：
     - 复制图片到 `wiki/tiddlers/` 对应子目录，并生成 `.meta`
     - 改写为 `[img[相对路径]]`
   - 解析 CSS 中的 `url(...)`：
     - 后续批量处理时一并复制并改写

### 4.4 HTML 清洗与转换

对每个 HTML 文件：

1. 读取并检测编码，统一转为 UTF-8
2. 提取 `<body>...</body>` 正文
3. 移除 `<script>`、`<style>`、DND3R 在线反馈区块（节点内不再保留单节点 CSS，统一由全局 `cascading_stylesheet.css` 控制）
4. 保留正文主体：标题、段落、表格、列表、引用、代码块
5. 标题处理：
   - 不注入 `font-size`，字号由全局 `cascading_stylesheet.css` 控制
   - 将 `align="center"` 转为 `text-align:center`
6. HTML 标签名统一转为小写，例如 `<H1>` -> `<h1>`
7. 自动补全 `<li>` 闭合标签，规范化 `<ul>` 嵌套，避免出现多余的 `</ul>` 或列表错位
8. 输出为清洗后的 HTML 片段，Tiddler 类型使用 `text/vnd.tiddlywiki`

### 4.5 生成 Tiddler

- 每个页面生成一个 `.tid` 文件，并**按源文件相对路径分目录存放**：

```text
wiki/tiddlers/0 核心三宝书/PHB玩家手册/2种族/人类.tid
```

```text
title: [PHB] 人类
tags: [[0 核心三宝书]] [[PHB玩家手册]] [[2种族]]
source: 0 核心三宝书/PHB玩家手册/2种族/人类.htm
type: text/vnd.tiddlywiki

<清洗后的 HTML>
```

- 目录由右侧边栏“目录”标签页展示（基于 `总目录`）
- 不再为每本书生成 `书名 - 目录`
- 当前默认首页通过 `$:/DefaultTiddlers` 指向“根目录 - 前言”

### 4.6 资源与链接处理

- 图片作为二进制 Tiddler 放入 `wiki/tiddlers/` 对应子目录
- 每个图片旁生成 `.meta` 文件：

```text
wiki/tiddlers/0 核心三宝书/DMG城主指南/封面.jpg
wiki/tiddlers/0 核心三宝书/DMG城主指南/封面.jpg.meta
```

```text
title: 0 核心三宝书/DMG城主指南/封面.jpg
type: image/jpeg
```

- HTML 中的图片引用改写为：
  - `[img[0 核心三宝书/DMG城主指南/封面.jpg]]`
- 对 `align="center"` 或 `width="100%"` 的图片，使用居中容器包裹：
  - `<div style="text-align:center;">[img[...]]</div>`
- 页面间链接改写为：
  - `<a href="xxx.htm">` -> `[[目标Tiddler标题]]`
  - 带锚点 `<a href="xxx.htm#sec">` -> `[[目标Tiddler标题#sec]]`
- 后续生成 `link-report.csv`，记录每个链接的源、目标、改写结果、是否失效

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 文件编码混乱（GBK/UTF-8 混合） | 先批量检测，再统一转换；转换后抽查 |
| CHM 内部链接使用 `#IDXHDR` 等特殊协议 | 忽略或映射到“总目录/索引” |
| 文件名含中文、空格、特殊符号 | 使用 Tiddler 标题字段，文件名仅作内部标识；必要时 URL 编码 |
| HTML 包含大量脚本/样式 | 清洗时剥离脚本，避免影响 TiddlyWiki 全局样式 |
| 表格/法术/怪物数据复杂 | 保留原始 HTML 表格，不强行转 Markdown |
| 图片路径为绝对路径或 `mk:@MSITStore:` | 用脚本归一化为相对路径并复制资源 |
| 图片 Tiddler 标题变成完整绝对路径 | 为每个图片生成 `.meta`，将标题设为相对路径 |
| Tiddler 标题重复 | 通过 `目录前缀 + 标题` 消歧，并记录映射表 |
| 全量转换后难以排查问题 | 改为按书/按分类逐步搬运，每批完成即检查 |
| 单文件 TiddlyWiki 体积过大 | 使用 Node.js 版 + 文件系统方式 |

### 8.1 WinCHM 默认文件名清理（2026-09-09）

- 现象：CHM 解压后部分页面源文件名为 WinCHM 自动生成的「新建主题.htm / 新建项目.htm」，转换脚本直接以源文件名为 `.tid` 文件名，导致 wiki 内出现 `新建主题.tid` / `新建项目.tid` 这类无意义文件名（其中 1 个连 `title` 与正文 h5 也是默认名，显示为「新建项目」节点）。
- 处理：全库扫描 `transport/wiki/tiddlers/` 下所有 tid，定位 **6 个**此类节点，按「文件名 = title 去后缀」惯例统一重命名：
  - `6 种族书/Dra巨龙之书/2/` 新建主题 → `封神之龙.tid`
  - `6 种族书/Dra巨龙之书/3/` 新建主题 → `猎龙者.tid`
  - `6 种族书/RoS石之族裔/1矮人/` 新建主题 → `矮人的生活.tid`
  - `8 战役引钩/EoE邪恶典范/` 新建项目 → `专长.tid`
  - `8 战役引钩/EoE邪恶典范/重要反派/` 新建项目 → `刻画反派.tid`
  - `1 核心补充书籍/MM4怪物图鉴4/怪物/精灵,卓尔/` 新建项目 → `卓尔女祭.tid`（该节点 title 与 h5 亦为「新建项目」，内容实为卓尔女祭怪物条目，已同步修正 title 与 3 处 h5 为「卓尔女祭」）
- 注意：`source:` 字段仍指向原始 `新建主题.htm`/`新建项目.htm`（源路径，未动）；TiddlyWiki 链接基于 title，改名不影响互链。验证重扫 `*新建*.tid` 已无残留。此后再遇 WinCHM 默认文件名节点，应同样规范为真实标题名（详见 `contexts.md` 第 7 节「WinCHM 默认文件名清理」）。
